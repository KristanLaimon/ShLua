# Lua 5.1 Transpiler Implementation Plan

## Context & Motivation
This plan was born out of the need to transpile `./hard_test.lua`, which currently throws errors when compiling anonymous functions, numeric `for` loops, and other complex features. While we could simply patch the transpiler to make that specific script work, that piecemeal approach would require continuously doing the same for future scripts, implementing the Lua 5.1 API in fragments and wasting too much time and tokens. Thanks to this symptom, this comprehensive feature and specification plan was drafted by the developer to solve the problem systematically at its root.

## ⚠️ CRITICAL AI INSTRUCTION: State & Context Management
To maintain continuity across multiple AI context windows and sessions, this project strictly relies on a file-based internal state management system using two files: `TODO.md` and `PROGRESS.md`.

**At the BEGINNING of every session, the AI MUST:**
1. Read `TODO.md` to identify the current active phase and pending tasks.
2. Read `PROGRESS.md` to understand what has already been built, internal state, architectural decisions, and how previous stages were implemented.

**At the END of every session, the AI MUST:**
1. Update `PROGRESS.md` with a detailed summary of what was just implemented, any edge cases handled, the current internal state of the AST/transpiler, and the active stage.
2. Update `TODO.md` by crossing off completed tasks and explicitly outlining the exact next steps for the following session.
Compacted so less tokens, this is for AI, not human reading.

## Phase 0: Project Initialization
- Create the initial `TODO.md` based on this exact plan, breaking it down into a checklist of pending tasks.
- Create the initial `PROGRESS.md` to document the starting state, target architecture, and shell compatibility constraints.
- *End of session: Update `TODO.md` and `PROGRESS.md`.*

## Phase 1: Lexer & Parser Foundations
- Reference: `./plan_specification.txt`
- Implement basic syntax parsing for Lua 5.1 (variables, primitives, operators).
- Establish AST (Abstract Syntax Tree) generation for basic expressions and assignments.
- *End of session: Update `TODO.md` and `PROGRESS.md`.*

## Phase 2: Control Structures
- Implement parsing and shell transpilation for conditional statements (`if`, `elseif`, `else`).
- Implement `while` and `repeat/until` loops.
- Implement numeric `for` loops (resolving the specific `./hard_test.lua` issues) and generic `for` loops (`in pairs/ipairs`).
- *End of session: Update `TODO.md` and `PROGRESS.md`.*

## Phase 3: Functions, Scope & Closures
- Implement standard function declarations and calls.
- Fix and implement anonymous functions (resolving `./hard_test.lua` issues) and closures.
- Handle Lua variable scoping (local vs global) and accurately map them to Bash/PowerShell scoping rules.
- *End of session: Update `TODO.md` and `PROGRESS.md`.*

## Phase 4: Bash Stdlib (Part 1 - Math & String)
- Create `./src/stdlib/bash/math.lua` and `./src/stdlib/bash/string.lua`.
- Implement Bash equivalents using dependency-free logic or standard Unix tools (e.g., awk, sed, python) adhering to `./docs/COMPATIBILITY.txt`.
- *End of session: Update `TODO.md` and `PROGRESS.md`.*

## Phase 5: PowerShell Stdlib (Part 1 - Math & String)
- Create `./src/stdlib/powershell/math.lua` and `./src/stdlib/powershell/string.lua`.
- Implement PowerShell equivalents utilizing standard out-of-the-box Windows tooling and .NET classes.
- *End of session: Update `TODO.md` and `PROGRESS.md`.*

## Phase 6: Advanced Stdlib (OS, IO, Table) for Both Targets
- Implement `os`, `io`, and `table` libraries for Bash in `./src/stdlib/bash/`.
- Implement `os`, `io`, and `table` libraries for PowerShell in `./src/stdlib/powershell/`.
- Validate OS-specific tooling constraints for these complex libraries.
- *End of session: Update `TODO.md` and `PROGRESS.md`.*

## Phase 7: Dependency Analysis & Injection Engine
- Build the AST analyzer to detect which standard libraries are actually used in the source Lua code (e.g., detecting `os.time` or `table.insert`).
- Create the engine that reads the required shell-specific stdlib files based on the analysis.
- *End of session: Update `TODO.md` and `PROGRESS.md`.*

## Phase 8: Bundling & E2E Validation
- Implement the bundler: Inject the required stdlib code at the very top of the transpiled `.sh` and `.ps1` outputs.
- Ensure the final output is one single, self-contained file with no external runtime dependencies.
- Run the full transpiler against `./hard_test.lua` and verify successful execution on both Bash and PowerShell.
- *End of session: Finalize `TODO.md` and `PROGRESS.md`.*
